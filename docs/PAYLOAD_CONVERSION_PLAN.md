## 1. Goal

Turn the static page `reference/portfolio-v4.html` into a **Next.js (App Router) + Payload CMS 3** project that:

- looks and animates **identically** to the reference (it is the source of truth for markup, CSS and motion);
- moves all content (profile, projects, experience, education, open source, copy) into the Payload admin so the owner edits it without touching code;
- deploys for free on **Vercel Hobby** with **Neon Postgres** and **Vercel Blob**, at a `*.vercel.app` address.

Owner: Sudipto Kumar Mitra, Senior Software Engineer at Idlewild Digital, Dhaka, Bangladesh. Personal portfolio, non-commercial (matters for the Vercel Hobby plan).

## 2. Decisions already made (do not re-open)

| Topic | Decision |
|---|---|
| Framework | Next.js App Router, TypeScript. Payload 3 runs inside the same Next app (`(payload)` and `(frontend)` route groups). |
| Scaffold | `npx create-payload-app@latest` with the **blank** template and the Vercel Postgres option. Run `--help` first and confirm flags; do not guess them. Do **not** use the `website` template (too much to delete). |
| Database | `@payloadcms/db-vercel-postgres` (Neon). Falls back to a normal Postgres connection when the URL is localhost. |

| Rich text | Keep the default `lexicalEditor()` that Payload requires. The frontend does not use it. |
| Styling | The design is bespoke CSS. **Port the CSS verbatim**: tokens and base styles into `globals.css`, each component's styles into a co-located **CSS Module**. Do **not** convert to Tailwind utilities and do not install Tailwind unless the owner asks. |
| Smooth scroll | `lenis` from npm (the reference loads 1.1.20 from a CDN). |
| Fonts | `next/font/google`: Bricolage Grotesque (display, with `opsz` axis, weights 300–800), Figtree (body), IBM Plex Mono (code), Caveat (handwritten notes). Expose them as the CSS variables the reference already uses: `--font-display`, `--font-body`, `--font-mono`, `--font-hand`. |
| Package manager | pnpm. |
| Pages | Single page `/`, statically generated, revalidated on content change. Plus `not-found.tsx`, `robots.ts`, `sitemap.ts`. |

Do not pin package versions from memory. Use whatever the scaffold installs and keep Payload packages on matching versions.

## 5. Frontend: section-to-component map

Server components load data; anything with state, timers, scroll or pointer events is a client component (`'use client'`). Keep every component small. Split the reference's single `<script>` into hooks and components.

| Reference section | Component(s) | Client? | Behaviour to preserve |
|---|---|---|---|
| `<head>` theme bootstrap script | inline script in `layout.tsx` via `dangerouslySetInnerHTML` | n/a | Adds class `js` to `<html>`, reads `localStorage['skm-theme-v3']` into `data-theme` **before paint** to avoid a flash. Add `suppressHydrationWarning` on `<html>`. |
| Tokens, base, `@media (prefers-color-scheme: dark)` + `[data-theme]` blocks | `globals.css` | n/a | Copy the three token blocks exactly. Keep `viewport-fit=cover` (export `viewport = { viewportFit: 'cover', ... }`) and the safe-area rules. |
| Nav pill | `Nav`, `ThemeToggle` | yes | Hides on scroll down after 160px, returns on scroll up. Theme toggle cycles light/dark, writes localStorage, updates `aria-label`. |
| Hero | `Hero`, `HeroName`, `CodeCard`, `NowCard`, `Stickers` | partly | Name lines slide up on load (CSS keyframes). Typed code card types once, caret blinks, reduced-motion shows it instantly (`CodeCard`). Stickers are draggable with pointer events and the `--x/--y` CSS variables; `touch-action: none`. Clouds drift (CSS). |
| "Tools I work with" strip | `TechMarquee` | no | Pure CSS marquee: two identical halves, the second `aria-hidden`, translate −50%, pauses on hover. Reduced motion: horizontal scroll, second half hidden. |
| Stack | `StackSection`, `LayerCard`, `Shape` | no | Three cards, `Shape` renders the inline gradient SVGs (`leaf`, `rings`, `slabs`) with **unique gradient ids** per instance (use `useId`). |
| Projects | `ProjectsSection`, `ProjectCard`, mocks | yes | **Sticky stacking cards**: each card is `position: sticky` with `top` offset by index; as the next card covers it, the previous scales down to 0.94 and dims (`useStackedCards`). Mocks: `LockMock` counts 60→0 then ticks both checkboxes, loops. `SerialMock` advances the serving number 12→15 every 2.6 s and updates the ETA. `ChatMock` is static. `ImageMock` = `next/image` screenshot in the same corner slot. |
| Experience | `ExperienceSection`, `Timeline` | yes | Centred timeline; line fill follows scroll (`--fill`), a node lights up when it passes 66% of the viewport. Cards alternate left/right on desktop, single column with the line at the left on mobile (≤760px). |
| Education | `EducationSection` | no | One card with the graduation-cap disc. |
| Open source | `OpenSourceSection` | no | Sticky intro on the left, link rows on the right with the lime bar and indent on hover. The "since September 2024" handwritten note is rotated. |
| Contact | `ContactSection` | no | Primary button is `mailto:` the profile email, then LinkedIn and GitHub buttons. |
| Footer | `Footer`, `GiantName` | yes | Lime panel, local-time clock for `profile.timezone` (render after mount to avoid hydration mismatch), giant name scaled to the panel width after `document.fonts.ready` and on resize, letters rise in on view. |
| Headings | `SplitHeading` | yes | Word-by-word mask reveal when 18% visible. Keep `aria-label` on the heading and `aria-hidden` on the split words. |
| Other reveals | `Reveal` (wraps `data-rise`) | yes | Fade and rise once. Content must be **visible without JavaScript**: only hide when `html.js` is set. |
| Smooth scroll | `SmoothScrollProvider` | yes | Lenis, `lerp: 0.09`. Anchor links scroll with offset −90. If reduced motion is on or Lenis is unavailable, use native scrolling. Share `scrollTo` through context for "Back to top". |

Global behaviours to keep:

- `prefers-reduced-motion`: disable every animation and reveal exactly as the reference's media query does.
- Sticky cards need ancestors **without** `overflow: hidden`. The reference uses `overflow-x: clip` on `body`. Keep that.
- Do not render anything time- or random-dependent on the server (clock, countdown, queue number). Initialise after mount.
- Every decorative SVG keeps `aria-hidden="true"`. Keep the hero `sr-only` summary, built from the profile.
- External links use `target="_blank" rel="noopener"`.
- Images: `next/image` only. No remote images except Payload media from Vercel Blob (`remotePatterns` for `*.public.blob.vercel-storage.com` in `next.config`).

## 6. Data access (service layer)

One file talks to Payload. Components never call Payload or `fetch` directly.

```ts
// src/services/portfolioService.ts
import { getPayload } from 'payload'
import config from '@payload-config'
import type { PortfolioData } from '@/types/portfolio'

export async function getPortfolio(): Promise<PortfolioData> {
  try {
    const payload = await getPayload({ config })
    const [profile, projects, experience, education, openSource] = await Promise.all([
      payload.findGlobal({ slug: 'profile' }),
      payload.find({ collection: 'projects', sort: 'order', depth: 1, limit: 50, where: { visible: { equals: true } } }),
      payload.find({ collection: 'experience', sort: '-start', limit: 50, where: { visible: { equals: true } } }),
      payload.find({ collection: 'education', sort: '-endYear', limit: 20, where: { visible: { equals: true } } }),
      payload.find({ collection: 'openSource', sort: 'order', limit: 50, where: { visible: { equals: true } } }),
    ])
    return {
      profile,
      projects: projects.docs,
      experience: experience.docs,
      education: education.docs,
      openSource: openSource.docs,
    }
  } catch (error) {
    console.error('[getPortfolio]', error)
    throw error
  }
}
```

`page.tsx` awaits `getPortfolio()` and passes plain props down. Map Payload types to small view-model interfaces in `types/portfolio.ts` where it keeps components simple. Add `error.tsx` so a database outage shows a friendly message instead of a crash.

`utils/buildCodeLines.ts` turns the profile into the typed code card lines (role, at, based, frontend, backend, cms, maintains). Frontend, backend and CMS lists come from `profile.layers[].chips`; `maintains` comes from `profile.codeMaintains`.

## 7. Revalidation (edit in admin → live site updates)

```ts
// src/collections/hooks/revalidateHome.ts
import { revalidatePath } from 'next/cache'
import type { CollectionAfterChangeHook, CollectionAfterDeleteHook, GlobalAfterChangeHook } from 'payload'

export const revalidateHome: CollectionAfterChangeHook = ({ doc, req: { payload, context } }) => {
  if (!context.disableRevalidate) {
    payload.logger.info('Revalidating /')
    revalidatePath('/')
  }
  return doc
}
export const revalidateHomeOnDelete: CollectionAfterDeleteHook = ({ doc, req: { context } }) => {
  if (!context.disableRevalidate) revalidatePath('/')
  return doc
}
export const revalidateHomeGlobal: GlobalAfterChangeHook = ({ doc, req: { context } }) => {
  if (!context.disableRevalidate) revalidatePath('/')
  return doc
}
```

Attach to every collection except `users`, and to the `profile` global. The seed script passes `context: { disableRevalidate: true }` because it runs outside Next.

## 10. Deployment guide (Vercel Hobby, free)

**Plan limits to respect.** The Hobby plan is for personal, non-commercial use only. A personal portfolio is the intended case. If the site ever sells services, runs ads or takes payments, move to Vercel Pro or another host. Hobby also allows a single team member.

### Before the first deploy

1. Develop locally until Phase 5 passes. Schema auto-push (`push: true`) is for development only.
2. Create the initial migration and commit it: `pnpm migrate:create` (name it `initial`). Commit `src/migrations/`. Without this the production database stays empty.
3. Confirm `pnpm build` passes locally.

### Deploy

1. Push the repo to GitHub.
2. Vercel dashboard → **Add New → Project** → import the repo. Framework preset: Next.js.
3. In the project: **Storage** → create a **Neon Postgres** database from the Marketplace and connect it to the project. This injects `POSTGRES_URL`.
4. **Storage** → create a **Blob** store and connect it. This injects `BLOB_READ_WRITE_TOKEN`.
5. **Settings → Environment Variables**: add `PAYLOAD_SECRET` and `NEXT_PUBLIC_SITE_URL` (use the project's `https://<name>.vercel.app` URL) for Production, Preview and Development.
6. Deploy. The build runs `payload migrate` then `next build`.
7. Open `https://<name>.vercel.app/admin` and create the **first admin user**. This screen only appears while no user exists, so do it immediately.
8. Seed production content: `vercel env pull .env.production.local`, point your local shell at those values, then run `pnpm seed` once. Alternatively enter the content by hand in the admin.
9. Upload the MediSerial screenshot in `media`, attach it to the MediSerial project, save. The site revalidates itself.

### After deploy

- **Rollback:** Vercel → Deployments → promote a previous deployment. Schema changes: write a new migration, never edit an applied one.
- **Schema changes later:** edit collections → `pnpm migrate:create` → commit → push. The next build migrates.
- **Custom domain (optional):** Vercel → Settings → Domains. The owner can keep the free `*.vercel.app` URL.
- **Security:** strong admin password; no public sign-up; restrict `users` creation to authenticated users.
- **Free-tier ceilings:** Blob storage and bandwidth are limited on Hobby. Keep screenshots under ~300 KB (convert to WebP before upload). Cron jobs are limited on Hobby and are not needed here.

## 11. Rules for Claude Code (copy into `CLAUDE.md`)

These come from the owner's own conventions. Follow them over generic advice.

- TypeScript everywhere, **not** `strict: true`. Enable `noImplicitAny` and `strictNullChecks`. Use `interface` for object shapes and `type` for unions. No `any`; use `unknown` and narrow.
- Folder layout as in section 3. Co-locate a component's CSS Module and types with it. Shared types in `src/types/`.
- Break the UI into small components. Keep reusable components simple. If making something reusable needs many props, keep it specific.
- API/data calls only in `src/services/`, never inside components. Always wrap them in `try/catch` and log with `console.error('[functionName]', error)`. Never write an empty `catch`.
- State: local `useState`/`useReducer`; Context API for theme and smooth scroll. **Do not install** Redux Toolkit, TanStack Query, Axios, React Hook Form or Zod. There is no form in this project.
- Do not add animation libraries (no Framer Motion, no GSAP). The reference uses CSS, IntersectionObserver and Lenis only.
- **Ask before adding any dependency** that is not in this plan.
- Use `next/image` for images. Dynamic-import nothing unless a bundle check shows it is needed.
- Preserve accessibility: keyboard focus styles, `aria-label`s, `aria-hidden` on decoration, reduced-motion support, sensible heading order.
- Do not invent content. Everything shown comes from the seed data in Appendix A or the CMS. If something is missing, leave it out and flag it.

## Appendix C: reference file map (`reference/portfolio-v4.html`)

| In the reference | Where it goes |
|---|---|
| `<style>` token blocks (`:root`, `@media (prefers-color-scheme: dark)`, `[data-theme="dark"]`) | `globals.css` |
| `<style>` base, `.chip`, `.btn`, headings, reveals | `globals.css` + `components/ui/*` modules |
| `<style>` per-section rules (hero, strip, stack, work, timeline, dark open-source, footer) | the matching feature component's CSS Module |
| `const TECH, LAYERS, PROJECTS, EXPERIENCE, EDUCATION, OSS, CODE` | CMS content, seeded from Appendix A |
| `shape()` function | `Shape` component (uses `useId` for gradient ids) |
| `MOCKS` object and countdown / queue timers | `projects/mocks/*` |
| scroll handler (`onScroll`, `updateCards`, `updateTimeline`) | `useStackedCards`, `Timeline`, `Nav` (each owns its scroll logic) |
| IntersectionObserver for `data-split` / `data-rise` | `SplitHeading`, `Reveal`, `useReveal` |
| Lenis setup and anchor handling | `SmoothScrollProvider` |
